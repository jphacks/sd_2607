# BSAF収集・再配信 — 既存の防災情報とMosimo投稿をつなぐ

Bluesky上のBSAF形式の投稿を収集し、Mosimo投稿と同じタイムラインで閲覧できるようにする機能です。BSAFは、防災情報を共通のタグで表現する形式です。別途有効化するpublisherにより、選択した投稿を署名付きでNostrへ再配信する機能も備えています。

## できること

- **選んだ発信元だけを収集**：運用者が登録した発信元のうち、BSAF形式を示すタグを持つ投稿を対象にします。
- **原投稿を保ったまま表示**：本文・著者・投稿の識別情報・タグを残し、出典をたどれる形でAppViewに保存します。
- **Mosimo投稿とまとめて取得**：共通のフィードAPIで一覧・ページング・発信者別の取得に対応します。
- **変更を反映**：投稿の更新・削除や収集許可の取り消しを索引へ反映します。
- **選んだ情報を再配信**：独立したpublisherが、許可したBot・情報種別の投稿を変換・署名し、設定したPDSのNostrリレーへ送ります。

## 工夫した点

- **既存の仕組みを活用**：HappyView本体を改造せず、追加の収集プロセスとフィード処理で接続します。
- **別の情報として出典を保持**：BSAF原投稿をMosimo投稿に見せかけず、取得元・取得時刻なども原投稿と分けて記録します。
- **無差別に集めない**：全Bluesky投稿を対象にせず、許可した発信元と形式に限定します。

## 現在の対応範囲

- collectorは原投稿の収集・表示を担当し、単体では変換・再配信しません。publisherは別プロセスで、既定では無効です。収集元を登録しても再配信は有効になりません。
- publisherによるBSAF再配信はNostr向けです。検証用の署名付き投稿・commit情報を構成しますが、PDSのatprotoリポジトリやfirehoseには公開しません。
- 収集元の登録は公的機関の認証ではありません。取得経路を信頼するモデルであり、原投稿のリポジトリ署名を独立に検証する機能ではありません。
- 新規登録時の過去投稿の一括取得には対応していません。長期間の停止後も、全投稿を回収できるとは限りません。
- 2026-10-18の収集機能の検証記録では、実Botのライブ収集は未有効化・未検証です。publisherの設定やローカル試験も、本番への有効化・継続稼働を示すものではありません。

> HappyViewへBSAF投稿を収集する構成ファイルを含みます。 [@https://github.com/oriom-dev/podman-cluster-config](https://github.com/oriom-dev/podman-cluster-config)のためのNixOSモジュールを含みます。
