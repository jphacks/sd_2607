# 時刻ヒント

識別子: `dev.jisaku.mosimo.mesh.time`

## 目的

本拡張は、`HELLO` の拡張配列に送信側の現在時刻と自己申告の信頼度を載せ、受信側が自分の時計との差を記録できるようにする。インターネットから長く切り離された端末や、電源断で時計が初期化されたマイコンは時計を大きく外し得る。接触した相手の時刻との差を知ることで、端末は自分の時計が極端にずれている可能性を検出し、利用者に表示できる。

本拡張の時刻は相手の自己申告であり、検証されていない。したがって本拡張は時刻の同期や正しい時刻の提供を保証せず、鍵署名の有効期間や配送期限の判定に使う時計を与えるものでもない。

## 前提

| 識別子 | 文書 | 依存する理由 |
|---|---|---|
| `dev.jisaku.mosimo.mesh` | [BPv7 メッシュ配送](../README.md) | `HELLO` の拡張配列と、時計が不明な端末の配送期限の扱い |
| `dev.jisaku.mosimo.attest` | [鍵署名](../../attest/README.md) | `keyValidity` の評価時刻として本拡張を用いてはならない対象 |

## 1. HELLO 拡張

```ts
type TimeHint = {
  $type: "dev.jisaku.mosimo.mesh.time";
  now: integer;        // 送信側の現在時刻、Unix 秒
  confidence: 0 | 1 | 2 | 3;
};
```

| `confidence` | 意味 |
|---:|---|
| 0 | 不明。時計の出所を判断できない |
| 1 | 低い。手動設定、または最後の同期から長時間経過している |
| 2 | 中程度。端末 OS の時計であり、最近ネットワーク時刻と同期した記録がある |
| 3 | 高い。GNSS 等の外部時刻源と現在同期している |

`now` は `HELLO` を送る直前に取得する。信頼度は送信側の自己評価であり、受信側はそれを検証できない。

## 2. 受信側の扱い

受信側は受信時刻 `local` との差 `delta = now - local` を、相手の node ID・`confidence`・受信時刻とともに記録する。記録は次の用途に限る。

- 自分の時計が極端にずれている可能性の検出。たとえば `confidence` が 2 以上の複数の相手との `delta` の絶対値が一定の閾値（例: 300 秒）を超え続ける場合、利用者に時計の確認を促す表示を出す。
- 表示。相手の時刻との差を診断情報として示す。

本拡張の時刻を次の判定の時計として採用してはならない。

- 鍵署名の `keyValidity` と失効状態の評価（鍵署名 §5.1）
- 配送期限（`mosimo:exp`）の満了判定
- 投稿の `created_at` の妥当性判定

これらは発信者の確認と配送の可否を左右する判定であり、本拡張の時刻は自己申告であるため、攻撃者が `now` を操作して期限切れの鍵署名を有効に見せたり、有効な投稿を期限切れとして捨てさせたりできるからである。時計が不明な端末は、コアの規則どおり期限内と確定できないものとしてローカル上限内で中継する。本拡張によって時計が確定したとみなしてはならない。

```mermaid
flowchart LR
  H[相手の HELLO の TimeHint] --> D[delta = now - local を記録]
  D --> W{confidence ≥ 2 の相手が複数、<br/>かつ |delta| が閾値を超え続けるか}
  W -->|はい| S[利用者に時計の確認を表示]
  W -->|いいえ| N[記録のみ]
  D -. 使ってはならない .-> K[鍵署名・配送期限・created_at の判定]
```
