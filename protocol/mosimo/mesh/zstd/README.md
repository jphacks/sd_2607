# 本文圧縮

識別子: `dev.jisaku.mosimo.mesh.zstd`

## 目的

本拡張は、双方が対応する接触において Bundle の payload 全体（メッシュ用 CBOR の配列）を zstd（RFC 8878）で圧縮して運ぶ手段を定める。本文の自然言語、CAP・気象庁 XML 由来の反復する語句、署名チェーンの共通部分は圧縮によって縮む。圧縮は運び方であり、受信側は復元後に通常の payload として検査する。本拡張は言語に依存せず、発信者の署名対象を変えない。

本拡張は圧縮率を保証せず、圧縮済みデータが元より短いことも保証しない。辞書の共有は任意であり、辞書なしの圧縮で完結できる。

## 前提

| 識別子 | 文書 | 依存する理由 |
|---|---|---|
| `dev.jisaku.mosimo.mesh` | [BPv7 メッシュ配送](../README.md) | `HELLO` の拡張配列、payload の構造とサイズ上限、`FETCH` による内容アドレス取得、`RESULT` |

## 1. HELLO 拡張

```ts
type ZstdCapability = {
  $type: "dev.jisaku.mosimo.mesh.zstd";
  dictionaries?: Bytes[];    // 保持している辞書の SHA-256（32 バイト）の一覧。省略時は辞書なしのみ
};
```

双方の `HELLO` に本拡張があるとき、その接触では送信側が Bundle ごとに圧縮の有無を選べる。`dictionaries` は送信側が復元に使える辞書の一覧であり、相手の一覧に含まれる辞書だけを圧縮に用いてよい。

## 2. 圧縮 payload

圧縮を用いる Bundle では、Payload Block の内容を次の 3 要素配列にする。

```cddl
compressed-payload = [
  mesh-version: 1,
  "zstd",
  frame: bstr
]
```

| 位置 | 項目 | 型・値 |
|---:|---|---|
| 0 | メッシュ符号化版 | 整数 `1`。コアの payload と同じ版 |
| 1 | 圧縮方式 | 文字列 `"zstd"` |
| 2 | 圧縮フレーム | 元の payload 配列（コア §2.1、鍵署名を参照に置き換えたものでよい）の CBOR バイト列を zstd で圧縮した一つのフレーム |

コアの payload は位置 1 が 32 バイトの `bstr`（公開鍵）であるため、位置 1 が文字列 `"zstd"` であることで圧縮 payload と区別できる。zstd フレームには `Content_Size` を含め、受信側は展開前に展開後の長さが payload 上限 32,768 バイト以下であることを確認する。上限を超える場合は展開せずに拒否する（`RESULT` 拒否、理由コード 2）。展開前の確認は、圧縮によって小さく見せた巨大な payload で受信側の資源を消費させる攻撃を防ぐためである。

辞書を用いる場合、zstd フレームヘッダーの `Dictionary_ID` に辞書の ID を入れる。辞書 ID は辞書の SHA-256 の先頭 4 バイトをリトルエンディアンの 32 ビット整数として読んだ値である。受信側は `Dictionary_ID` から辞書を特定し、手元になければ辞書の SHA-256 を知っている場合に限り `FETCH` で取り寄せられる。SHA-256 全体を知らない辞書 ID の Bundle は拒否する（理由コード 6）。辞書 ID の先頭 4 バイトだけでは衝突を排除できず、別の辞書で展開した結果を誤って検証にかけることになるためである。

```mermaid
flowchart TD
  A[Bundle を受信] --> B{payload 位置 1 が "zstd" か}
  B -->|いいえ| V[コアの payload として処理]
  B -->|はい| C{Content_Size ≤ 32,768 か}
  C -->|いいえ| X[拒否: 理由 2]
  C -->|はい| D{Dictionary_ID はあるか}
  D -->|ない| E[辞書なしで展開]
  D -->|ある| F{辞書を保持しているか}
  F -->|はい| G[辞書で展開]
  F -->|いいえ| H{辞書の SHA-256 を知っているか}
  H -->|はい| I[FETCH で辞書を取得] --> G
  H -->|いいえ| Y[拒否: 理由 6]
  E --> V
  G --> V
```

展開後のバイト列はコアの payload 配列であり、鍵署名の復元、イベント ID と署名の検証、サイズ上限の確認をコアの規則どおりに行う。圧縮 payload のまま保存・中継・Nostr へ搬出してはならない。本拡張に対応しない相手が復号できず、署名対象の検証もできないためである。保存は展開後の payload で行い、次の接触で相手が対応していれば再圧縮する。

`BEGIN` の全長と `HELLO` の `maxBundleBytes` は圧縮後の Bundle のバイト数で計る。payload の 32,768 バイトは展開後で計る。

## 3. 辞書

辞書は zstd の辞書形式のバイト列であり、SHA-256 で内容アドレスされる。大きさは 16,384 バイト以下とし、`FETCH` の 1 オブジェクトとして取得できる。辞書の配布元・作成方法・更新は本拡張の範囲外であり、辞書の SHA-256 を `HELLO` で示し合えた相手の間でだけ辞書付き圧縮が成立する。辞書なしの圧縮は常に使え、辞書の取得に失敗した送信側は辞書なしで再送してよい。
