# 情報の有効期間

識別子: `dev.jisaku.mosimo.validity`

## 目的

本プロトコルは、投稿内容がいつの状況・指示として有効かを表す「情報の有効期間」を、投稿の拡張として定義する。避難指示の適用期間や警報の対象期間のように、原情報が明記する期間を構造化情報として保持し、対応クライアントが期間に基づく表示・整理を行えるようにすることが目的である。

本書が保証するのは、著者が記した期間の端点がそのまま保持・復元されることである。有効期間は配送期限とは別の概念であり、有効期間の終了は投稿の削除・撤回を意味しない。省略された端点は不明であり、無期限に有効であることも意味しない。

## 1. 型

```ts
type ValidityExtension = {
  $type: "dev.jisaku.mosimo.validity";
  from?: Timestamp;
  until?: Timestamp;
};
```

| 項目 | 必須 | 意味 |
|---|---|---|
| `from` | 任意 | 内容が有効になる時刻 |
| `until` | 任意 | 内容が有効でなくなる時刻 |

時刻の表記と精度は[コア §3.1](../README.md#31-共通時刻型-timestamp)に従う。正規の定義は [`lexicon.json`](lexicon.json) である。

## 2. 三つの時間の区別

| 時間 | 所有者 | 意味 |
|---|---|---|
| 作成時刻 `created_at` | Nostr イベントの標準フィールド | 投稿を作成した時刻 |
| 情報の有効期間 `from`〜`until` | 本拡張 | 内容がその時点の状況・指示として有効な期間 |
| 配送期限 `exp` | 投稿の基本項目 | 新たなメッシュ配送の対象とする期限 |

有効期間と配送期限は独立に設定する。配送期限が有効期間より先に満了することも、有効期間の終了後も配送期限内であることもある。有効期間の終了を根拠に投稿を削除・撤回したものとして扱ってはならない。削除は著者の制御処理（[コア §11](../README.md#11-削除)）だけが表すためである。

## 3. 省略と不明

有効期間の拡張自体は任意である。拡張がない投稿、または端点が省略された投稿の該当する端点は不明である。不明な端点を、配送期限、受信時刻、作成時刻、現在時刻のいずれからも補ってはならない。補った値は著者が主張していない期間を署名付きの情報として表示することになるためである。

## 4. 原情報の時刻との対応

原情報が持つ現象発生時刻と有効開始時刻は異なる概念である。取り込み側は、CAP の `onset` や BSAF の `time:` のような原情報の時刻項目を、その意味が有効期間の開始・終了に一致する場合に限り `from`・`until` へ対応付ける。意味を確認せずに置き換えてはならない。発生時刻を開始時刻として配送すると、まだ有効でない指示を有効として表示するためである。原表記が必要な場合は[公的情報](../public/README.md)の出典に保持する。

## 5. Nostr 上の表現

[コア §7.3](../README.md#73-自己完結した拡張タグ)の自己完結した拡張タグで運ぶ。

```text
["mosimo:ext:dev.jisaku.mosimo.validity", B64(C({from?, until?}))]
```

`C` は atproto deterministic CBOR、`B64` は padding なしの通常 Base64 である。内部の時刻は原表記の文字列のまま保持する。
