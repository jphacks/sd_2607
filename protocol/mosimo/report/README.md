# 通報

識別子: `dev.jisaku.mosimo.report`

## 目的

利用者が不適切と判断した投稿を、他の利用者・中継ノード・サーバーに知らせる方法を定義する。通報は [NIP-56](https://github.com/nostr-protocol/nips/blob/master/56.md) の `kind: 1984` イベントであり、投稿と同じくメッシュとリレーで運ぶ。運営者への個別の連絡経路を前提とせず、圏外でも通報を伝えられるようにする。

本プロトコルが保証するのは、通報が通報者の鍵で署名されていること、対象の event ID と通報の種別を誰でも同じ形で読めることである。

通報は通報者の判断の表明であり、投稿内容が不適切であることの証明ではない。通報の件数は、Nostr の鍵がインストールごとに自由に作れるため、通報者の数や意見の分布を表さない。通報を受けたノードやサーバーが何を基準に、何をするかは実装と運用者が決める。投稿の著者による削除は[削除要求](../delete/README.md)が扱う。

## 前提

| 識別子 | 文書 | 依存する理由 |
|---|---|---|
| `dev.jisaku.mosimo` | [コア](../README.md) | Nostr イベントの構造、発見用 `t` タグ、配送期限タグ `mosimo:exp` |
| `dev.jisaku.mosimo.mesh` | [メッシュ配送](../mesh/README.md) | kind を問わない保存・中継、配送候補・照合集合の扱い |

## 1. イベント

通報は対象 1 件につき 1 件の `kind: 1984` イベントとし、通報者の Nostr 鍵で署名する。

| 項目 | タグ配列 | 個数 |
|---|---|---|
| プロトコル識別 | `["t", "mosimo.jisaku.dev"]` | 1 個 |
| 対象 | `["e", <対象の event ID>, <種別>]` | 1 個 |
| 対象の著者 | `["p", <対象の pubkey>, <種別>]` | 1 個 |
| 配送期限 | `["mosimo:exp", Timestamp]` | 1 個 |

- タグはこの表の順に置く。`e` と `p` の種別は同じ値とする。
- `content` は通報者の任意のコメントであり、UTF-8 で 280 バイト以下とする。コメントも公開される。
- 配送期限は対象の配送期限より前に満了しないことを推奨する。アプリの既定値は、対象の配送期限と作成時から 24 時間の遅い方とする。

種別は NIP-56 の値を用いる。

| 種別 | 意味 | アプリでの表示例 |
|---|---|---|
| `spam` | 宣伝・繰り返し等、目的に関係のない投稿 | スパム・宣伝 |
| `profanity` | 誹謗中傷・差別・脅迫等の不快な表現 | 不快な表現・嫌がらせ |
| `illegal` | 法令に反する内容 | 違法な内容 |
| `impersonation` | 他人・機関へのなりすまし | なりすまし |
| `nudity` | 性的な内容 | 性的な内容 |
| `malware` | 有害なリンク・ファイル | 有害なリンク |
| `other` | 上記以外。虚偽の災害情報、他人の個人情報を含む | その他 |

受信側は未知の種別を `other` として数える。自分の投稿に対する通報（`pubkey` が `p` と一致するもの）は無視する。

## 2. 集計と配送の停止

ノードは対象の event ID ごとに、通報した Nostr 公開鍵の集合を保持する。同じ通報者による複数の通報は 1 件として数える。

| 状態 | ノードの扱い |
|---|---|
| 異なる通報者の数が閾値未満 | 対象を通常どおり扱う。通報を受けたことを表示に反映してよい |
| 閾値以上 | 対象の表示をやめ、配送候補・照合集合・`INVENTORY` から外す。保存している本体は消去してよい。以後は `WANT` せず、`BEGIN` を受けた場合は理由コード 5 で拒否する |

閾値は実装が決める。本書の参照実装（Android・iOS・ESP32）は 2 とする。対象が未着の時点で閾値に達した場合も、対象の event ID を記録して後から届いた対象に適用する。

通報そのものは閾値に関わらず、通常のイベントとして配送期限まで保存・中継し続ける。対象の配送を止めても通報を止めないのは、後から対象を受け取るノードにも通報を伝えるためである。

通報者は[削除要求](../delete/README.md)で自分の通報を取り下げられる。取り下げられた通報は集計から除く。閾値を下回っても、一度停止した配送を再開するかは実装が決める。

閾値による停止は各ノードの配送方針であり、[メッシュ配送 §10](../mesh/README.md#10-非表示とブロック) のブロックと同じく、他者に配送の停止を要求するものではない。ノードは通報者の重み付け（[署名チェーン](../attest/chain/README.md)で確認できた通報者を重く数える等）や、特定の対象（確認済みの公的情報等）への閾値の変更を行ってよい。

## 3. サーバー

- Nostr リレーと PDS のリレーは `kind: 1984` を受け付け、保存・配信する。
- 運用者は自身のサーバーに届いた通報を確認し、自身のサーバーでの配信停止や投稿者の配信停止を行える。この措置は運用者のサーバー上の扱いであり、著者の署名済みリポジトリを書き換えるものではない。PDS は通報を根拠に著者の commit を生成してはならない。
- 運用者が通報を確認する期限・基準は運用者が定め、利用規約等で示す。

## 4. 濫用と限界

- 鍵は自由に作れるため、一人が複数の通報者を装える。閾値は正当な投稿の配送を止める手段にもなり得る。災害時の配送を妨げる損害と、不適切な投稿を広げる損害の釣り合いで閾値を決める。
- 通報は公開情報である。通報者の公開鍵・コメント・対象が第三者に知られる。
- 通報は内容の訂正ではない。内容の誤りの指摘は[注釈](../annotation/README.md)の訂正として発信する。
