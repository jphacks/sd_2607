# 0003: 未決事項と仕様化の順序

状態: draft-00

本書は未解決事項の一覧であり、選択肢を採用済みとして扱うものではない。設計対話は一度に一つの判断を確認し、結果を関連文書へ反映する。

## 1. ID と署名

- オフラインで生成可能な ID と、標準 atproto が受け入れる DID method の両立。
- 初回 DID Document 相当イベントの形式と、その内容を信頼する根拠。
- atproto の署名鍵と Nostr 公開鍵の結び付け、鍵・署名アルゴリズムの選定。
- 同一 DID の単一 writer、再インストール、OS バックアップ復元、巻き戻り、鍵侵害・失効。

## 2. 投稿・交換データ

- 正式名称・識別子・Lexicon NSID・版管理。
- レコード、commit、Nostr タグの正確な対応と検証順序。
- 本文重複を避けつつ元の署名対象バイト列を復元する方法。
- CBOR の決定的符号化、CID、数値・時刻・文字列・未知拡張の取り扱い。
- 発信地点・影響範囲のスキーマ、座標系、精度、円・多角形・地域コード等の対応範囲。
- サイズ・ネスト・要素数・本文長等の資源上限。

## 3. リポジトリの同期

- CAR slice と、操作・レコードからの MST 再構築方式の比較。
- base 状態の特定、順序逆転、欠落取得、検証待ち状態。
- 古い状態や fork の検出と解決。
- 配送同値によるイベントの省略と、個々のリポジトリ復元の両立。

## 4. 削除・訂正

- 投稿イベントと削除要求、atproto の削除操作の対応形式。
- 削除要求と対象イベントの同一著者検証、先行到着時の保留。
- 削除要求の保持期間、再投入抑制、未接続期間との関係。
- 訂正参照、連鎖、複数訂正、他者の訂正の表示。
- 配送同値グループの代表イベントが削除された場合の扱い。

## 5. メッシュ配送

- アプリ間相互接続の発見方法と BLE・Wi-Fi 等のリンク仕様。
- OS のバックグラウンド制限と実装可能な接触・転送モデル。
- BPv7 の endpoint、bundle 構成、フラグ、登録・未登録コードの検証。
- 接触時の inventory・要求・転送形式と資源制限。
- 時計ずれ、寿命、hop、再バンドル、重複排除記録の寿命。
- 地域内優先・範囲外抑制・ゲートウェイ搬出の具体規則。
- priority の濫用、Sybil、DoS、断片化・再組み立て。

## 6. オンライン公開と冗長化

- Nostr kind・検索可能なタグ・リレー互換性・保存方針。
- リレー発見方式、既知 AppView の役割、既定リストの障害耐性。
- PDS 公開 endpoint と DID の対応、標準 Relay の同期要件。
- 複数独立サーバーの発見・複製・保存・公開方法。
- 既存 Relay が重複 commit をどう扱うかの一次仕様・実装確認。
- AppView と Nostr の二経路取得時の同一投稿判定。

## 7. 原情報取り込み

- 既定の取り込みサーバーと信頼リストの更新・失効。
- 情報源別の原情報 ID、版、訂正・取消、原文ハッシュ。
- 決定的変換の版管理、時刻・多言語・表記揺れ。
- 配送同値キーと検証・代表選択の具体形式。
- CAP・EDXL・気象庁 XML の対応範囲と変換時の情報損失。
- BSAF の収集とメッシュ投入の区別、出典・地域コードの扱い。

## 8. 仕様完成の条件

- 一次仕様への規範参照と固定リビジョン。
- 署名・変換・MST 復元・削除・配送同値のテストベクトル。
- 未知拡張、欠落、順序逆転、時計ずれ、偽装の異常系。
- 複数実装間の往復変換と相互通信の検証。
- サイズ計測と資源上限の妥当性確認。

現時点では実装、テストベクトル、相互運用試験はない。
