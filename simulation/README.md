# もしもシミュレーター

災害の直後からインターネットが戻るまでの間に、情報がどう伝わるかを一人ひとりの単位で再現し、もしもプロトコルを実装したアプリの導入率によって何が変わるかを調べる Tauri アプリです。計算はすべて Rust（`core/`）で行い、画面（`src/`）は結果を表示して操作を送るだけです。

参考にしたのは [避難所IF！（jphacks/tkb_2615）](https://github.com/jphacks/tkb_2615) です。避難者一人ひとりをエージェントとして扱い、同じシードで条件だけを変えて比べる、という考え方を引き継ぎました。対象は避難所の運営ではなく、通信と情報の伝達です。

## シナリオ

| シナリオ | 範囲 | 期間 | ねらい |
|---|---|---|---|
| 避難所一つ（珠洲市 宝立小中学校） | 宝立町周辺、約2,200人 | 10日 | 小さな範囲を細かく再現する。収容287人に800〜900人が避難し、Starlinkが届いたのは1/7以降 |
| 川内キャンパス全体（東日本大震災） | キャンパスと周辺、約1,400人 | 7日 | とんペディア（学生の約9割が利用）にプロトコルを入れた場合を想定する。2011-03-11 14:46、春休み中 |
| 能登半島全体 | 奥能登6市町、約13.1万人（実人口） | 21日 | 大きな範囲を再現し、公表された記録で調整する。発災から携帯がおおむね復旧するまで |

能登と避難所の住民は実際の分布に置きます。

- 人口と高齢化率: 国勢調査2020の500mメッシュ（e-Stat）を、市町ごとに2024-01-01の推計人口へ合わせ、帰省客として1.1倍します（倍率は推定）。
- 住居の位置: 世帯をメッシュ内の実在の建物（OpenStreetMap）に置きます。
- 津波の判定: 家ごとの標高と海岸からの距離（地理院DEM）で決めます。
- 地区: OSMの地名（町・字）ごとにまとめます。避難所は実在の学校・公民館です。近くに避難所がない地区には、住民が開いた自主避難所を置きます。
- 道路: OSMの国道・県道です。

道路の寸断と地区ごとの被害率は推定です。数値の出典と推定箇所は `core/scenarios/generate.py` のコメントと、アプリの「出典」タブにあります。

## モデル

- **人**: 世帯ごとに配置します。年齢、携帯の有無、キャリア、電池残量、iPhoneかどうか、アプリの有無、域外の家族の有無を持ちます。避難所・車中泊・在宅を選び、津波から逃げ、家や電波の届く高台へ出かけ、一部は域外へ去ります。
- **通信**:
  - 携帯の基地局は、市町ごとの停波率の推移（内閣府の停波局数と市町別の支障解消日から補間）に従って止まり、復旧します。
  - 輻輳による通話・データの成功率を扱います。
  - 船上基地局「きずな」、可搬型・車載型の基地局、有線給電ドローン、高台で拾える遠くの局も含めます。
  - 避難所のStarlinkは端末容量と衛星セル容量を共有し、輻輳します。
  - Starlink Directは反実仮想です。au対応端末が屋外にいるとき、ビーム容量を共有してSMSやSOSを送ります。オプションでデータも送れます。
  - ほかに、衛星電話、固定回線、緊急速報メール、テレビ・ラジオ、防災行政無線を扱います。
- **人から人へ**:
  - 対面の会話: 優先度の高い情報から数件ずつ伝えます。
  - 避難所の掲示板と受付: 着いた人が知っていることを受付に伝えます。
  - 自治体職員の巡回・伝令、物資トラックの運転手も情報を運びます。
- **もしもプロトコル**:
  - アプリ同士が近距離で出会うたびに、持っている投稿を交換します。交換できる量は次のように決まります。
    - 到達距離: 屋外40m、屋内15mです。家と家の間は壁があるのでその6割です。
    - 接触時間: 止まっている者同士は1ステップずっと接しています。すれ違いは「1.4×到達距離÷相対速度」秒です。
    - 発見までの時間: Android同士は約10秒、iPhoneが混じると約1分、バックグラウンドのiPhone同士は約10分です。
    - 接続準備: 約4秒かかります。
    - 通信速度: 約100kbpsです。
    - 時間内に送れないときは、優先度拡張で要救助を先に送ります（なければ古い順）。
  - 投稿の大きさは、atproto の commit を含む署名付き Nostr イベントとして約2KBです。公的情報は署名チェーンを含めて約4KB、安否は約1.5KBです。
  - インターネットにつながった端末はゲートウェイになり、運んできた投稿をアップロードし、新しい投稿を持ち帰ります。
  - 避難所の名簿は、1件の投稿に集約して運べます（集約安否）。
  - 本部はAppViewで位置付き・署名付きの投稿を見ます。SNSだけで流れた要請は後回しにします。
- **カーナビ**: 世帯の車のナビが、ある割合でプロトコルに対応しているとします。
  - 動くのは走行中と車中泊（アイドリング）の間だけです。車のバッテリーで動くので、スマホの電池切れに左右されません。
  - ルーフのアンテナで80m届きます。
  - 「無事」ボタンで、運転者が同乗する家族の分まで安否を投稿できます。
  - 通信モジュール付きの車（コネクテッドカー）は、基地局が生きていればアップロードします。
  - 車中泊の半分は避難所の駐車場に集まります。救助隊・物資トラック・巡回車も同じ割合でナビを積みます。
- **人による伝達**:
  - 対面の会話、避難所の掲示板と受付で情報が広がります。
  - 区長・民生委員が約1.5日間、近所を一軒ずつ回って安否を確かめ、避難所の名簿に加えます。
  - 自治体職員の巡回・伝令、物資トラックの運転手も情報を運びます。
- **対応**:
  - 市町の本部と県・救助機関の間は、回線の状態に応じて情報が流れます（インターネットなら全部、衛星電話なら要点だけ）。
  - 救助隊は近い順・重傷優先で出動し、道路の寸断を知らなければ立ち往生します。
  - 何も通報がなければ、被害の大きい地区を捜索します。
  - 物資は、県が把握している避難所に届けます。要請と人数をもとに配り、本部が知らない自主避難所には届きません。
  - 要救助者は阪神・淡路大震災の救出時間と生存率に基づいて亡くなります。家族や近所の人が助け出せる軽傷者もいます。

### 記録する重大イベント

救助が間に合わない（原因を「発見されず／情報が届かず／隊が足りず／到着前に」に分類）、津波到達時に浸水域に残留、避難所の水・食料が尽きた、物資が集中しすぎ、孤立集落や避難所を本部が把握していない、寸断を知らず車両が立ち往生、偽の救助要請に出動、Starlink・Starlink Directの輻輳、安否不明の長期化。

## 使い方

[mise](https://mise.jdx.dev) が Rust・Node.js・uv を揃えます。

```sh
mise install                 # ツールを入れる
mise run dev                 # アプリを起動（初回は npm ci も行う）
mise run build               # 配布用にビルド
mise run build-linux         # Linux 向け（.deb・.rpm・.AppImage）を Ubuntu 22.04 のコンテナでビルド（podman が必要）
mise run build-mac-x64       # Intel Mac 用の .dmg をビルド（Apple Silicon の Mac で）
mise run publish-hp          # ビルドしたインストーラーを ../hp のダウンロードページに置く
mise run installer-images    # インストーラーの画像を作り直す（Windows のみ）
mise run installer-images-macos # DMG の背景と mac 用アイコンを作り直す（mac のみ）
mise run test                # シミュレーションのテストと型チェック
mise run sim -- noto 0 0.5 0.9 --seeds 3              # 画面なしで計算し、導入率ごとの平均を出す
mise run sim -- noto 0 0.4 --carnav-sweep --adoption 0 # カーナビの普及率だけを変える
mise run sim -- noto 0 0.9 --trace --hours 168        # 重大イベントを原因別に集計
mise run experiments         # 実験一式を回し、experiments/report.md に書く（数時間かかる）
mise run scenarios           # generate.py からシナリオを作り直す
mise run geo                 # 人口・建物・道路・標高を取り直す（e-Stat・OSM・地理院からダウンロード）
```

地図は地理院タイル（淡色地図）を暗く表示するため、インターネット接続が必要です。

画面の左で条件を変え、「この条件で開始し直す」を押します。中央の地図では、点の色を「通信」「安否」「情報」で切り替えられます。「情報」では、選んだ情報を誰が知っているかが分かります。右の「比較実験」は、同じ条件で導入率（スマホまたはカーナビ）だけを変えて最後まで計算し、指標を表で比べます。同じシードなら人の配置と被害が同じになるので、違いは導入率だけから生じます。

## 限界

- 公表されていない値は推定です。輻輳時の通話成功率、道路の寸断区間、地区ごとの全壊率、船上基地局の到達範囲、Starlinkの衛星セル容量、市町ごとの停波率、カーナビの普及率が該当します。値に強く依存する結論は、比較実験で感度を確かめてください。
- 帰省客は住民と同じ家に置いています。観光客の分布は再現していません。
- 要救助者の救出には救助隊の数と道路が強く効きます。情報が早く届いても、救助隊が足りなければ死者は減りません。「救助隊の規模」を変えて、どちらが制約になっているかを確かめられます。
- カーナビは、持ち主が人から聞いたことも送れるものとしています（画面で入力する想定）。
