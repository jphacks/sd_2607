## Critical fix

A verified PLC genesis control event (`kind=8173`, MNDT §9.5) previously reached `main.cpp::showMessage` with no kind information. Its JSON body replaced the latest human text preview and entered the speech queue. Deletion and other control kinds had the same problem.

- `BundleInfo.kind` now carries the original, signature-verified Nostr kind.
- `showMessage` displays/enqueues speech only for `kind=1`. This is a presentation filter, not full protocol/DID validation; generic verified Nostr kind-1 text remains displayable.
- Control events are still verified, durably saved, ACKed and forwarded unchanged. No control payload is discarded or rewritten for presentation.
- Red/green evidence: the new actual-main test failed at `M5.Display.previews.size() == previews && M5.Display.headings.size() == headings` before the filter. It passes afterward for PLC 8173, deletion 5, kind 0 and unknown 65535; ordinary kind-1 reception and mute/radio independence still pass.

## Exact compatibility expectations for today's demo

**Keep Android on MNDT §9 on the ESP32 link.** Do not switch this link to §3 CBOR HELLO or numbered GATT frames without coordinated implementation/testing.

- Service `b5e89a01-f9da-45c2-9111-2de7a7441d24`.
- RX (Android central → ESP32): `483c3867-c832-4c60-9a96-7018059eaf74`; use the current Android write-with-response pacing. ESP32 also exposes WRITE_NR, but does not implement the agreed §3 credit scheme.
- TX notification (ESP32 → Android): `49d60590-c23f-4a0a-a58e-f2f2f606f94d`; subscribe before exchange.
- Legacy advertisement: service UUID list; scan response service data = UUID + 8-byte node ID + flags `01` (peripheral-only).
- Byte stream: 4-byte big-endian message length, then JSON control (`hello/inventory/want/ack`, `v=1`) or indefinite-outer BPv7 Bundle beginning `9f`. Chunk at `min(MTU-3,512)`, do not assume MTU 517 was granted.
- HELLO: 16 lowercase-hex node ID, `max=24000` from ESP32. Respect the peer max; keep demo bundles comfortably below it. Node ID is not an author identity.
- Current destination: `dtn://mosimo.oriom.dev/~post`; age/hop blocks required, lifetime ≤86,400,000 ms, local maximum hop 8. These are §9 provisional choices, not finalized global EID/retention requirements.
- Payload: `[1, pubkey(32 bytes), created_at Unix seconds, kind, tags, content UTF-8, sig(64 bytes)]`.
- Ordinary posts: kind 1; exactly the standard base tags from 0012 §3.2.4: `t=mosimo.oriom.dev`, `mosimo.oriom.dev:version=1`, commit, base (empty string for initial commit, not omitted), path `dev.oriom.mosimo.post/<13-character TID>`, created-at and delivery-expires-at. Commit/ext values use unpadded **standard**, not URL-safe, Base64 when restored to Nostr. No additional action/record-type tags are required.
- Online Android publishes the **original** event and signature; do not republish ESP32's display/speech-sanitized text or create a new event. ESP32 changes only BPv7 forwarding metadata/CRCs.
- For both display and speech, use a short Japanese kind-1 notice **≤2,000 UTF-8 bytes**. Display previews the first 40 codepoints. Longer valid bodies can store/relay/display but do not speak. Queue is latest-priority with 3 jobs, recent-ID speech dedup 64; no guarantee every burst item speaks.
- Keep ESP32 powered during source-phone → ESP32 → receiving-phone handoff. Reset/smoke-test/upload would make saved entries cold. Existing installed firmware is unchanged by this audit.
