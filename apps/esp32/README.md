# Mosimo ESP32 — 投稿を預かり、次の端末へ渡す中継ノード

M5Stack Basic（ESP32）を使った、公開テキスト投稿のBluetooth中継デモです。Androidから投稿を預かり、後で接続する別のAndroidへ渡します。新着本文の表示・日本語読み上げも端末だけで行います。任意のgatewayビルドでは、ESP32自身のWi-Fiでオンライン搬出や認可済み公的情報の手動取得も行えます。

## 役割・主要機能

- **時間差の中継**：送信元のAndroidが離れた後でも、電源を維持したESP32から次のAndroidへ投稿を引き渡せます。
- **検証して保存**：署名や転送回数・経過時間を検査し、受け取った投稿を端末内に保存します。
- **本文表示・読み上げ**：検証・保存に成功した新着投稿を画面と音声で知らせます。同じ投稿の重複受信では読み上げません。
- **任意のWi-Fi搬出・取得**：明示設定したgatewayビルドは、元の署名を保ってNostrリレーへ搬出し、PLC初期登録を代理送信できます。公的情報の取得は追加の信頼設定・時計の明示的信頼が必要で、既定は無効です。
- **ボタンで操作**：通常版のAは読み上げテスト、gateway版のAは公的情報の取得要求です。BはBluetoothのみを切り替え、Internet通信は止めません。音声対応版のCはミュートで、中継の有効設定は変えません。

## 工夫した点

- **確かに保存してから受理応答**：書き込んだ内容を読み直して確認し、保存失敗時に受理済みと見せません。転送時も投稿者の署名を保ちます。
- **小さな端末で無理なく動かす**：保存量と処理待ちの量に上限を設け、重い処理をBluetoothのコールバックから分離しています。gateway＋音声版はBluetooth・TLS・音声の資源利用を時間分割します。
- **重複取得を抑える**：保存先から退避した投稿も受信履歴に残します。履歴と保存先が満杯になると、新規取得を止めて既存投稿の中継を続けます。gateway版は搬出未確認の投稿も退避せず保護します。
- **通信と音声を独立させる**：音声の準備に失敗しても中継を止めず、クラウドでの音声合成も不要です。ただしgateway＋音声版は音声・ネットワーク処理中にBluetoothを切断・休止するため、相手の再接続・再試行が必要です。

## 実装範囲・制限

- Androidとの[暫定通信形式](../../protocol/mndt.md#9-android-実装の暫定値提案未採用)を使う実験実装です。接続相手は一度にAndroid 1台で、ESP32同士の接続、投稿作成には未対応です。通常版・診断版はオフライン専用で、Internet通信には明示設定したgateway版が必要です。
- **電源断・再起動前に保存した投稿は、再起動後にはメッシュ中継しません**。電源断中の経過時間を正しく測れず、配送期限を延ばさないための制約です。gateway版のオンライン搬出はcold投稿も再試行しますが、メッシュ中継の資格は復活しません。実電源断を挟む耐障害性や長時間耐久性は未検証です。
- 公開投稿専用で、Bluetooth通信路自体の暗号化や相手の本人確認は行いません。gateway通信はTLS検証を行いますが、署名も内容の真実性を保証しません。リレー受理・PLC登録・PDS公開・Web表示は別の段階です。
- **読み上げは評価専用**です。ナ行・マ行が「ヌ」になる制限があり、正確な防災放送や製品運用には使えません。音声SDK・辞書・それらを含むファームウェアは公開せず、利用・配布には[公式条件](https://www.a-quest.com/download.html)の確認が必要です。音声なしgateway版と、資源を時間分割するgateway＋音声版があります。
