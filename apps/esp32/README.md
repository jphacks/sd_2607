# Mosimo ESP32 — 投稿を預かり、次の端末へ渡す中継ノード

M5Stack Basic（ESP32）を使った、公開テキスト投稿のBluetooth中継デモです。Androidから投稿を預かり、後で接続する別のAndroidへ渡します。新着本文の表示・日本語読み上げも端末だけで行います。

## 役割・主要機能

- **時間差の中継**：送信元のAndroidが離れた後でも、電源を維持したESP32から次のAndroidへ投稿を引き渡せます。
- **検証して保存**：署名や転送回数・経過時間を検査し、受け取った投稿を端末内に保存します。
- **本文表示・読み上げ**：検証・保存に成功した新着投稿を画面と音声で知らせます。同じ投稿の重複受信では読み上げません。
- **ボタンで操作**：読み上げのテスト、通信の切り替え、音声のミュートができます。ミュート中も中継は続きます。

## 工夫した点

- **確かに保存してから受理応答**：書き込んだ内容を読み直して確認し、保存失敗時に受理済みと見せません。転送時も投稿者の署名を保ちます。
- **小さな端末で無理なく動かす**：保存量と処理待ちの量に上限を設け、重い検証処理で通信を妨げない構成にしています。
- **重複取得を抑える**：保存先から退避した投稿も受信履歴に残します。履歴と保存先が満杯になると、新規取得を止めて既存投稿の中継を続けます。
- **通信と音声を独立させる**：読み上げ処理を分離し、音声の準備に失敗しても中継を止めません。クラウドでの音声合成は不要です。

## 実装範囲・制限

- Androidとの[暫定通信形式](../../protocol/mndt.md#9-android-実装の暫定値提案未採用)を使う実験実装です。接続相手は一度にAndroid 1台で、ESP32同士の接続、インターネットへの送信、投稿作成には未対応です。
- **電源断・再起動前に保存した投稿は、再起動後には中継しません**。電源断中の経過時間を正しく測れず、配送期限を延ばさないための制約です。実電源断を挟む耐障害性や長時間耐久性は未検証です。
- 公開投稿専用で、通信路自体の暗号化や相手の本人確認は行いません。署名も内容の真実性を保証しません。
- **読み上げは評価専用**です。ナ行・マ行が「ヌ」になる制限があり、正確な防災放送や製品運用には使えません。音声SDK・辞書・それらを含むファームウェアは公開せず、利用・配布には[公式条件](https://www.a-quest.com/download.html)の確認が必要です。
