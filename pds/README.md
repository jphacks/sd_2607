# Mosimo PDS — 端末の署名を保ったままatprotoへつなぐ

圏外で作成し、端末同士で運んだ投稿をオンライン側へつなぐサーバーです。Nostr経由で投稿を集め、署名とデータの整合性を確かめて、atprotoの配信網へ公開します。投稿者の秘密鍵は持たず、署名も代行しません。

## 役割・主要機能

- **投稿を集める**：端末から直接、または外部のNostrリレーから署名済み投稿を受け取ります。
- **正しく復元する**：端末が作った投稿データを復元し、登録された公開鍵で署名と内容の整合性を検証します。
- **オンライン側へ公開する**：正規の公開先としての条件を満たした投稿を、RelayやAppViewなどの後段サービスへ提供します。
- **サーバー間で補完する**：承認済みのサーバー同士で更新を知らせ、必要な元データを取得して再検証します。

## 工夫した点

- **受け取りと公開を分ける**：受理応答を返しても、検証が終わるまでは公開しません。投稿者の署名を保ち、サーバー側で作り直さない設計です。
- **届く順番が逆でも待てる**：復元に必要な過去の投稿が未着なら保留し、後から再試行します。古いデータで公開状態を巻き戻しません。
- **切断後も続きから配信**：更新と配信履歴を一緒に保存し、受信側が再接続した際の再送に対応します。
- **規模に応じて構成を選べる**：単一サーバー向けの保存方式に加え、複数サーバーで共通のデータベースを使う構成も選べます。

## 実装範囲・制限

- **公開テキストの新規作成（create）のみ**を扱います。一般のBluesky PDS一式ではなく、通常のクライアントからの投稿操作、ログイン、画像・音声の保存は提供しません。
- 投稿者の識別情報が事前に登録されていることが前提です。鍵の変更をまたぐ過去署名の検証、アカウント移行への自動追従、欠落データの完全回収には未対応です。Nostr側の鍵とatproto側の識別情報の対応も認証済みとは扱いません。
- 削除要求に対する対応は配信の抑止です。保存データの物理消去や、atproto側の削除データの作成は行いません。
- 大規模運用では処理時間・保存容量に制約があり、負荷試験や大容量配信の全経路試験は未実施です。全機能・全条件での互換性を保証するものではありません。

> Nostrリレー兼AT Protocol PDSを運用する構成ファイルを含みます。 [@https://github.com/oriom-dev/podman-cluster-config](https://github.com/oriom-dev/podman-cluster-config)のためのNixOSモジュールを含みます。
